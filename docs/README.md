# VoiceBridge — документация проекта

Голосовой ассистент для разработчиков. Десктоп-приложение (macOS + Windows) на
стеке Rust + Tauri, живёт в системном трее. Распознаёт речь локально (без
интернета) и управляет OpenCode.

## Модель интерфейса

- **Главное окно** — лаунчер: список проектов (запуск/остановка серверов
  OpenCode, «＋ Новый» с выбором папки) и список сессий запущенных экземпляров.
  Клик по сессии открывает окно чата. Сессии с открытым окном помечаются
  бейджем «открыта»; при закрытии окна выбор сессии сбрасывается.
- **Окно чата** (по одному на сессию) — основной интерфейс общения: сверху
  название сессии и имя проекта, ниже полный диалог («Вы» / «OpenCode» с
  markdown и подсветкой синтаксиса), инструменты, запросы действий
  (разрешения/вопросы — в отдельном «доке» над полем ввода, всегда на виду),
  история сессии. У каждого ответа — кнопка копирования и время выполнения
  (тикает в реалтайме и замирает по завершении). Пока OpenCode думает, в строке
  состояния над полем ввода показывается статус («работает…» / «выполняет
  `read`…»); если событий нет дольше 90 с — предупреждение «возможно, завис» с
  кнопкой прервать. Внизу — панель ввода: текстовое поле + кнопка отправки +
  голосовая кнопка (тап/удержание). Ниже — строка состояния: токены сессии и
  стоимость. Справа (или оверлеем на узком окне) — Git-панель: изменённые файлы,
  сгруппированные по папкам, с диффом по клику. Окна изолированы друг от друга
  по сессиям.

## Режим работы

Наговоренный текст отправляется как промпт в выбранную сессию OpenCode, ответ
стримится в окно чата.

> GUI-автоматизация (вставка текста в выбранное окно) отложена на самый конец —
> объёмная задача (см. «Планы» ниже).

## Стек

- **Бэкенд**: Rust, Tauri 2 (`src-tauri/`).
- **Фронтенд**: React 19 + TypeScript + Vite 7 (`src/`).
- **Захват звука**: `cpal` 0.18.
- **Распознавание речи**: `whisper.cpp` через `whisper-rs` 0.16 (Metal на Apple
  Silicon).
- **HTTP**: `reqwest` (blocking + json).
- **Markdown**: `react-markdown` + `remark-gfm` + `rehype-highlight`
  (подсветка синтаксиса).
- **Иконки**: `lucide-react`.
- **Звуки**: Web Audio API (синтез на лету, без аудиофайлов).

## Поток данных

1. Запись (в окне чата): `cpal` пишет сэмплы в буфер + считает RMS-уровень →
   событие `audio-level` (волна в UI).
2. Остановка → буфер ресемплится в 16 кГц mono → задание в STT-поток.
3. STT-поток (владеет `WhisperContext`) транскрибирует → `finish_transcription`.
4. В режиме OpenCode → `send_prompt` → `POST /session/{id}/message` + чтение
   SSE `GET /event` → стриминг ответа в окно чата.

## Запись и ввод

Голосовая кнопка в окне чата: **тап** = переключение (старт/стоп), **удержание** =
запись пока держишь (отпустил — стоп). Есть авто-остановка по тишине (настройка
в «Настройки → Микрофон»). Глобальный хоткей `⌘⇧V` / `Ctrl+Shift+V` тоже
работает и настраивается в «Настройки → Горячие клавиши».

Рядом — текстовое поле: сообщение можно набрать и отправить кнопкой отправки
или Enter.

**Режимы отправки** (настройка «Настройки → OpenCode → Режим отправки»):
- **Сразу в чат** — распознанный текст сразу уходит в сессию.
- **Предпросмотр** — распознанный текст попадает в поле ввода, отправляешь сам.

Текущий режим показывается бейджем в панели ввода; клик по бейджу переключает
режим. При «сразу в чат» текстовое поле скрыто.

## Сессии изолированы

Окна чата независимы друг от друга. Запись, индикатор записи и превью
распознанного текста привязаны к сессии конкретного окна (поле
`recording_session_id` в `AppState`), а не к глобальному состоянию. Хоткей и
трей-меню без окна используют выбранную в лаунчере сессию.

## Звуки и индикатор ответа

- Начало/конец записи, отправка сообщения и получение ответа сопровождаются
  короткими синтезированными звуками (Web Audio API, `src/sounds.ts`).
- Пока OpenCode формирует ответ, в чате показывается анимированный индикатор
  «думает» (три точки).

## OpenCode

Подробности API и типы событий — см. `docs/OPENCODE.md`.
Коротко:

- Обнаружение: процессы `opencode` через `lsof` (macOS/Linux) или
  `netstat`+`tasklist` (Windows) + порты 4096/12000/3000/17000.
- Сессии: `GET /session`; история: `GET /session/{id}/message`.
- Отправка: `POST /session/{id}/message`; стрим — SSE `GET /event`.
- Проекты: список из БД (`opencode db`), запуск/остановка `opencode serve`
  из приложения (стабильный порт по хэшу пути) + создание нового инстанса с
  произвольной рабочей папкой. Папки, запущенные через «Новый проект» (ещё без
  сессий в БД), запоминаются в `AppState.known_worktrees` и подмешиваются к
  списку (`list_projects_with_extra`), чтобы не пропадать при обновлении.
- Действия: запросы разрешений (`permission.asked`) и вопросы (`question.asked`)
  обрабатываются в окне чата (разрешить/запретить, варианты ответа).

## Сборка и запуск

```bash
npm install
npm run tauri dev     # dev
npm run tauri build   # релиз (.dmg / .exe)
```

Требования: Rust (rustup), Node 20+, cmake (для whisper.cpp), Xcode CLT
(macOS) или MSVC Build Tools + LLVM (`libclang.dll` для bindgen whisper-rs,
`LIBCLANG_PATH` на `<LLVM>\bin`) (Windows). Первая сборка компилирует
whisper.cpp (несколько минут).

## Автообновление

Подключён `tauri-plugin-updater`. Конфиг в `src-tauri/tauri.conf.json`
(`plugins.updater`): endpoint — `latest.json` из GitHub Releases, вшит
публичный ключ подписи. Проверка обновлений — команда `check_update`
(кнопка «Проверить обновления» в «Настройки → О программе»).

Ключ подписи:

- приватный — `src-tauri/voicebridge-signing.key` (в `.gitignore`, не коммитить);
- в CI приватный ключ передаётся через env `TAURI_SIGNING_PRIVATE_KEY`
  (секрет репозитория).

Генерация/подпись артефактов пока **выключена** (`bundle.createUpdaterArtifacts`
не задан) — иначе сборка требует приватный ключ. Чтобы включить: добавить
секрет `TAURI_SIGNING_PRIVATE_KEY` в репозиторий и задать
`"createUpdaterArtifacts": true` в `bundle`, затем публиковать артефакты +
`latest.json` в релиз. Также нужны подпись/нотаризация `.app` (macOS) и
`.msi`/NSIS (Windows).

## Логи

Лог пишется в папку логов приложения: `voicebridge.log`
(macOS: `~/Library/Logs/com.voicebridge.app/`, Windows:
`%APPDATA%\com.voicebridge.app\logs\`). Туда пишутся старт, загрузка/скачивание
модели, транскрипция, обнаружение инстансов, ошибки и паники.

## Известные особенности / грабли

- `src-tauri/.cargo/config.toml` принудительно ставит `SDKROOT=""` и
  `MACOSX_DEPLOYMENT_TARGET=10.15`. Первое — иначе при `SDKROOT=iPhoneOS` сборка
  whisper.cpp падает на FindBLAS; второе — иначе в новых Xcode сборка падает на
  `std::filesystem` (требует macOS 10.15+).
- Типы событий SSE OpenCode **не совпадают** с OpenAPI-схемой (см.
  `docs/OPENCODE.md`).
- Обычный TUI `opencode` не открывает TCP-порт — нужно `opencode serve` или
  `opencode web`.
- Capability `windows: ["*"]` обязательна, чтобы динамические окна
  `response-{sessionId}` получали события.

## Планы

1. **Рефакторинг под современную архитектуру** — приоритет. Сейчас часть файлов
   разрослась до 1000+ строк (например, `src/App.tsx` ~1700, `src/styles.css`
   ~2400, `src-tauri/src/modules/opencode.rs` ~1300,
   `src-tauri/src/commands.rs` ~880, `mobile/lib/screens/sessions_screen.dart`
   ~540). Нужно разбить на модули/компоненты по ответственности, выделить
   общий слой состояния и хелперы, вынести UI-компоненты и стили, убрать
   дублирование между десктопом и мобилкой. Ветка `refactoring`.
2. **Git-панель изменений** (десктоп + мобилка) — Трансляция файлов, которые
   система (OpenCode) меняет в проекте: список изменённых файлов (`git status`)
   с количеством добавленных/удалённых строк и диффом (до/после) по клику. На
   десктопе окно чата responsive: при достаточной ширине справа показывается
   встроенная панель, при узком окне — кнопка с выезжающей боковой панелью
   (overlay). На мобилке — отдельный экран (навигация).
3. **GUI-автоматизация** (вставка распознанного текста в выбранное окно) —
   отложена на самый конец. Это объёмная задача: системные API для списка окон
   (macOS `CGWindowListCopyWindowInfo`, Windows `EnumWindows`) и вставка текста
   (симуляция нажатий клавиш / буфер обмена + Ctrl/Cmd+V / Accessibility API).
   В текущей сборке не реализована.
