# Промпт для продолжения сессии (новая сессия)

Скопируй текст ниже целиком в новую сессию агента, чтобы продолжить работу над
проектом VoiceBridge с текущего состояния.

---

Продолжи работу над проектом **VoiceBridge** — голосовым ассистентом для
разработчиков (Rust + Tauri, macOS/Windows). Проект уже на продвинутой стадии.

**Сначала прочитай эти файлы (в них полный контекст):**
1. `docs/AGENTS.md` — структура, команды, конвенции, критичные грабли.
2. `docs/README.md` — обзор архитектуры и фич.
3. `docs/OPENCODE.md` — проверенный API OpenCode (типы SSE-событий!).

**Как запускать:** `npm install`, затем `npm run tauri dev` (dev) или
`npm run tauri build` (релиз). Проверка Rust: `cargo check` в `src-tauri/`,
фронтенда: `npm run build` в корне.

**Что уже реализовано и работает:**
- Трей с меню, глобальный хоткей записи (Cmd+Shift+V / Ctrl+Shift+V),
  сохранение состояния между запусками.
- Захват звука (cpal) с визуализацией уровня, выбором микрофона и
  чувствительностью.
- Локальный STT через whisper.cpp (whisper-rs, Metal на Apple Silicon): реестр
  моделей (Tiny/Base/Small/Medium, Qwen3-ASR — «скоро»), скачивание с прогрессом,
  выбор языка; модель Base — по умолчанию (автоскачивание).
- **Главное окно — лаунчер**: панель проектов (запуск/остановка `opencode serve`,
  «＋ Новый» с выбором папки) + панель сессий; клик по сессии открывает окно чата.
- **Окно чата** (по одному на сессию, изолированы друг от друга): сверху
  название сессии и имя проекта, ниже полный диалог («Вы»/«OpenCode» в
  markdown с подсветкой синтаксиса), стрим в реальном времени, чипы
  инструментов, история сессии, обработка действий OpenCode (запросы
  разрешений `permission.asked` — разрешить/запретить, вопросы `question.asked`
  — варианты ответа). У каждого ответа кнопка копирования; пока OpenCode
  думает — анимированный индикатор.
- **Панель ввода в чате**: текстовое поле + кнопка отправки (иконка/Enter) +
  голосовая кнопка (тап = переключение записи, удержание = говорить,
  авто-остановка по тишине).
- **Режимы отправки** (настройка «OpenCode → Режим отправки»): «сразу в чат»
  (по умолчанию) или «предпросмотр» — распознанный текст идёт в поле ввода,
  отправляешь сам. В чате отображается текущий режим (клик по бейджу —
  переключение); при «сразу в чат» поле ввода скрыто.
- **Изоляция сессий**: запись, индикатор записи и превью привязаны к сессии
  окна (`recording_session_id`); открытые сессии трекаются и помечаются в
  лаунчере бейджем «открыта», при закрытии окна выбор сбрасывается.
- Звуковые отклики (запись/отправка/ответ) через Web Audio API, иконки
  `lucide-react`.
- Windows-обнаружение/остановка OpenCode: `netstat -ano -p TCP` + `tasklist`
  для портов/PID, `taskkill /PID <pid> /F` для остановки, `where opencode` для
  поиска бинаря.
- Подсветка синтаксиса в markdown (`rehype-highlight` + тёмная hljs-тема).
- Настройки заполнены (Модели, Микрофон, OpenCode, Вставка, Горячие клавиши,
  О программе). Файловый логгер (`voicebridge.log`) + перехват паник.
- CI: GitHub Actions собирает `.exe` (Windows) и `.dmg` (macOS) по тегу `v*`.

**Что НЕ сделано (кандидаты на продолжение):**
- **GUI-автоматизация** — `src-tauri/src/modules/automation.rs` возвращает
  пустой список; нужны системные API: на macOS `CGWindowListCopyWindowInfo`
  для списка окон, на Windows `EnumWindows`; вставка текста (симуляция клавиш /
  буфер обмена + Ctrl+V). Команда `list_windows` и настройки вставки уже есть.
- Qwen3-ASR, автообновления (Tauri updater).
- Запуск opencode на Windows через `.cmd`-шим (`cmd /C`), если `where` вернул
  `.cmd`.

**Ключевые грабли (подробно в docs/AGENTS.md):**
- `src-tauri/.cargo/config.toml` форсит `SDKROOT=""` и
  `MACOSX_DEPLOYMENT_TARGET=10.15` (иначе whisper.cpp не соберётся). Не удаляй.
- Реальные типы SSE-событий OpenCode — `message.part.delta` / `message.part.updated`
  / `session.idle`, а НЕ `session.next.*` из OpenAPI-доки.
- Обычный TUI `opencode` не открывает TCP-порт; нужен `opencode serve`/`web`.
- Capability `windows: ["*"]` — обязательна для динамических окон
  `response-{sessionId}`.

Начни с того, что подтверди понимание текущего состояния (прочитай docs/),
проверь сборку, затем спроси/уточни, что именно делаем дальше (по умолчанию —
GUI-автоматизация).
